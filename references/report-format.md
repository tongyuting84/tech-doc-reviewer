# 评审报告格式

使用“汉堡包”五段式，顺序和 emoji 固定；内容可按问题数量压缩。

## 1. 总体结论

一句话说明是否可发布、是否需修改后发布、或因 P0 阻断。列出已评审范围和未核验范围。

## 2. 🚨 阻断问题

仅列 P0。没有时写“未发现 P0 阻断问题”。每条使用：

- **[P0][规则 ID] 问题标题**
  - 原文：可定位片段
  - 证据与影响：为什么构成风险
  - 修改建议：可执行且不捏造事实

## 3. 🔍 必须修改

列 P1，格式同上。技术事实问题说明影响路径；格式问题不要夸大风险。

## 4. ✅ 优化建议

列 P2 与“待人工确认”。待确认项必须说明缺少的证据，不计入确定问题总数。

## 5. 🎉 正向总结与下一步

肯定已做好的具体点，汇总 P0/P1/P2 数量，给出最短修复顺序；写明质检记录是否已写入、未写入或失败原因。

## 报告约束

- 每条问题必须有等级、规则 ID、原文定位、影响和建议。
- 同一位置的同类问题合并，避免重复计数。
- 不因规则标为“强制”就自动定 P0。
- 允许提供结构和通顺度改写；新增事实使用占位说明或要求作者补证据。
- 链接检查分别报告可达性、目标一致性、锚点准确性；未完成的检查不得写“通过”。
