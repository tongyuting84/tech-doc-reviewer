## 规则字段

`references/rules/` 中每条规则均包含：

- **ID**：稳定引用标识，格式为 `来源-领域-序号`；融合规则可保留原 ID 并并列来源。
- **来源**：W、W2、W3、W4、W5、B、E 或组合。
- **效力**：`强制`、`条件强制`、`建议` 或 `强制边界`。
- **默认等级**：常规影响的起点，最终按 `severity-and-compliance.md` 动态裁决。
- **适用场景**：规则生效的载体、内容类型或评审尺度。
- **例外/人工核验**：不应机械命中的情况及所需证据。

`references/principles/` 不作为机械规则表；它说明目的、判断信号和评审方式。`references/methods/` 是可选写作工具，必须根据适用场景选择，不得强迫所有文档套模板。

## 使用方式

1. 报告引用最具体的规则 ID，不写泛化的“违反规范”。
2. 一处文本触发多条规则时合并为一条可执行问题，列主要和辅助规则，避免重复计数。
3. 无规则来源时不得临时创造硬规则；可给不计数的“经验建议”。
4. 依赖模板、旧产品库、固定像素、字体或渲染的要求，只在当前平台规范或可见证据下判定。
5. 维护规则时以本文件的来源映射和稳定规则 ID 为索引，权威内容仅落在 `rules/`、`principles/`、`methods/` 及必要执行层文件中；迁移审计不作为运行时来源。

## 冲突与严重性

1. 法律、安全、隐私和真实生产风险优先。
2. 当前产品事实与平台约束优先于旧规范。
3. 同等条件下，后续业务实践 B 优先于 W/W2；W3/W4/W5 按各自场景补充，不自动覆盖更具体的已有规则；E 只限制证据和误报。
4. “强制”表示规范效力，P0/P1/P2 表示本次影响，二者不得混用。
5. 无法裁决时保留原文并标记“待人工核验”，说明缺少的证据。
