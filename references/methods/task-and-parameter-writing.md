# 任务与参数写作方法

## 操作任务闭环

- **适用场景**：快速入门、用户指南、运维操作、排障和任何可执行流程。
- **输入**：目标结果、环境/权限、输入资源、真实操作路径、成功证据、已知失败和恢复方式。
- **步骤**：
  1. 写清目标、适用/不适用场景。
  2. 列出必要前提、权限、版本、网络/地域、依赖、输入和风险。
  3. 按真实顺序写原子步骤，每个关键阶段提供可检查的中间状态。
  4. 给出成功判据，包括页面状态、输出、日志或指标。
  5. 对常见失败写“现象—判别—处理”；高风险变更补备份、回滚和恢复。
  6. 用声明环境走查；不能实测时标注未实测范围。
- **输出**：能执行、能验证、失败可处理的任务文档。
- **禁用/不适用**：纯概念或索引页不必套完整步骤；不得凭经验编造 UI、错误码或回滚命令。

## 参数说明

- **适用场景**：文本框、枚举、多选、开关、权重/优先级、复杂表达式和策略配置。
- **输入**：字段定义、类型、来源、默认值、范围、特殊值、选项差异、依赖、风险和示例。
- **步骤**：
  1. 用一句话说明参数控制什么，避免“X 参数：配置 X 参数”。
  2. 说明使用场景、配置来源/方式和与其他参数的依赖。
  3. 按类型补充：
     - 文本框：格式、来源、默认值/范围、注意事项；
     - 选项：总述后逐项解释差异、影响、推荐场景；
     - 开关：默认状态及开/关两种结果和风险；
     - 权重/优先级：范围、数值方向、边界和特殊值；
     - 灵活配置：给可验证示例并拆解关键部分。
  4. 核对正文、UI、API、示例和输出一致。
- **输出**：读者可据此作出正确配置选择的说明；可用表格、列表或短段落。
- **禁用/不适用**：自明字段不堆砌无信息句；无证据的默认值和推荐值留作待核验。

## 总—分表达

- **适用场景**：多个并列选项、分类或步骤前需要先建立共同语义。
- **输入**：共同目标、分类标准、各项差异。
- **步骤**：先给总述，再按同一维度逐项说明，最后在必要时给选择建议。
- **输出**：总述 + 平行列表/表格。
- **禁用/不适用**：单项或上下文已清晰时不为形式重复总述。
