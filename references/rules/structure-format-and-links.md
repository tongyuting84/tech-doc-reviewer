### W-DESC-01 短描述执行细则

- **检查对象**：文档列表页摘要、标题下方简介、SEO 之外由作者维护的短描述。
- **推荐结构**：第一句回答“这是什么/能做什么，适用于谁或什么场景”；第二句回答“本文介绍哪些操作或内容”。
- **错误示例**：标题为“创建实例”，短描述仍只写“创建实例”；或罗列“步骤 1、步骤 2、步骤 3……”等易变章节。
- **推荐改法**：`云服务器实例提供可弹性扩展的计算资源，适用于部署应用和运行计算任务。本文介绍创建实例所需的前提、配置项和操作步骤。`
- **避免内容**：重复标题、枚举过细章节、复制目录、写入频繁变化的按钮路径或步骤编号。
- **防误判**：“通常两句话”不是机械句数门禁。一句话已清楚覆盖两层信息、平台字数受限或模板另有要求时不报；只有遗漏关键信息或明显重复时给 P2 建议。

|---|---|---|---|---|---|---|
| B-LINK-01 | 检查可达性：跟随完整跳转链后，目标页面可被普通目标用户实际访问，不能只以 HTTP 200 判定通过 | W+B | 强制 | P1 | 所有链接 | 登录、白名单、权限、地域限制需记录实际页面内容与用户可见结果；若无法模拟目标用户环境则标待核验 |
| B-LINK-02 | 检查目标一致性：必须抓取或读取跳转后的正文、标题、状态页提示等实际内容，确认与锚文本语义一致；仅凭状态码、最终 URL、路由名或页面外壳不得判定通过 | B | 强制 | P1 | 所有链接 | 无需逐字相同，但正文主题、用户任务和链接承诺必须一致；白名单、登录拦截、占位页、错误页均按实际影响报告 |
| B-LINK-03 | 检查锚点准确性：实际打开链接并确认最终定位到正确章节，而非仅验证基础页面可达 | B | 强制 | P1 | 锚点链接 | 动态锚点无法验证时待核验 |
| W-LINK-04 | 正文使用有意义的锚文本，避免无必要裸露长 URL | W | 建议 | P2 | 正文链接 | API 地址、命令输出或需复制 URL 时可裸露 |
| W2-LINK-05 | 链接服务必要跳转，不用链接替代当前任务必需信息 | W2+W5 | 建议 | P2 | 正文、表格 | 导航、索引、参考资料集可高密度使用 |
| W2-LINK-06 | 外部/跨产品通常适合新页签，同文档锚点/连续任务通常适合当前页签 | W2 | 条件强制 | P2 | 可配置链接行为的平台 | 以平台能力和体验规范为准；源文本不可见时待核验 |
| W2-LINK-07 | 发布前按当前平台验证锚点生成和定位 | W2 | 条件强制 | P1 | 锚点链接 | 不沿用旧“最多三级”限制 |

### W-PUNC-03 空格执行细则

- **应加空格**：中文与英文之间，如“支持 Kubernetes 集群”；中文与阿拉伯数字之间，如“创建 3 个实例”。
- **不加空格**：全角标点前后无需额外空格，如“支持 ECS、VPC 和 CLB。”；数字与百分号之间，如“成功率为 99%”。
- **按语法/官方名称**：代码 `fooBar`、URL、路径、参数、命令、`10Gbps`、`4K`、产品固定名称或商标不拆分。
- **等级与防误判**：孤立空格通常 P2；大面积格式混乱或造成词义/代码错误时可升 P1。网页抽取中标签断词、表格粘连、代码/UI 标签拆分先按 `../false-positive-prevention.md` 还原，不机械报错。

### B-PUNC-05 连接符执行细则

- **数值范围 `～`**：表示连续数值区间，两侧不留空格，例如 `1～5 GB`、`10%～20%`。不要写 `1 - 5` 或 `1—5`。
- **一字线 `—`**：表示地点、时间等起止或语义连接，例如“北京—上海链路”“配置—验证流程”。不要与中文破折号“——”混用。
- **短划线 `-`**：用于日期和图表编号，例如 `2026-10-12`、`图 2-1`；也保留在代码、参数 `--help`、负数、标准编号和协议语法中。
- **全半角边界**：中文句子标点仍用全角；英文、代码、URL、路径、命令和参数内部使用半角语法字符。
- **默认等级**：通常 P2；只有连接符错误改变范围、日期、参数或技术含义时按影响升 P1。

Markdown 源码风格本身不是评审目标；只有导致渲染、链接、代码含义或内容错误时按实际影响报告。
