## 代码与命令执行细则

### W-CODE-01 代码、配置与 YAML

- **检查对象**：代码块、行内代码、YAML/JSON、配置片段及其预期输出。
- **判定条件**：语法无法解析；变量、函数、参数或依赖不存在；缩进改变语义；同级 YAML 键缩进不一致；正文与示例输入输出矛盾；示例缺少必要片段而未说明省略。
- **错误示例**：同一对象下的 `name` 缩进 2 个空格而 `image` 缩进 4 个空格；命令使用正文未定义的变量；示例输出与参数含义相反。
- **推荐改法**：按目标语言格式化；统一同级缩进；补充依赖、版本和省略标记；在可用环境中执行或解析示例，并写明验证结果。
- **默认等级**：通常 P1；仅样式不统一但语义无误可为 P2；会导致泄露、数据丢失、越权或严重生产故障时升 P0。
- **防误判**：不能运行不等于示例错误。缺少环境、权限或产品事实时写“静态检查通过/执行结果待核验”，不得假称已执行。
- **YAML 片段省略例外**：技术文档为突出需要新增或修改的字段，可使用独立的 `...` 表示中间内容已省略。满足以下条件时，不得仅因整段无法通过 YAML 解析而报告语法错误：
  1. 标题、引导语、注释或上下文能让读者识别该代码是局部片段，而非可直接应用的完整清单；
  2. `...` 仅承担省略标记作用，没有被描述为真实配置字段或可复制内容；
  3. 展示的重点字段仍保留足够的父级结构，读者能判断其层级和归属；
  4. 省略未掩盖完成当前操作所必需的依赖、风险或关键参数。
- **例外失效**：若文档声称示例可直接复制执行，或 `...` 与真实 YAML 文档结束标记混用而造成语义歧义，或展示部分本身存在缩进错误、层级不明、字段归属错误，仍按 W-CODE-01 报告。此时只报告可确认的具体问题，不笼统表述为“出现 `...`，所以 YAML 错误”。

### W-CODE-02 命令可执行性

- **检查项**：目标 Shell/操作系统、工作目录、权限、依赖、换行续写、引号/转义、提示符与输出是否可复制区分、占位符是否需要替换。
- **错误示例**：把 `$` 提示符包含进复制命令；Linux 命令用于 Windows 却未说明；占位符写成疑似真实值；缺少必须的当前目录。
- **推荐改法**：将命令与输出分块；明确“将 `<your-id>` 替换为实际值”；标注运行环境和目录；高风险命令先给验证、备份和回滚步骤。
- **事实边界**：无法确认参数是否存在、输出是否准确时标待核验，不凭常识补产品事实。

## UI 动词执行细则

- **标准映射**：按钮—“单击”；文本框—“输入”；开关—“开启/关闭”；复选框—“勾选/取消勾选”；滑块—“滑动”；下拉框—“选择”。
- **应报告**：动作与控件类型不匹配，例如“输入开关”“勾选文本框”；UI 名称与当前界面证据不一致；动作会导致用户无法完成步骤。通常 P1，轻微但可理解的不一致可为 P2。
- **不单独报告**：`单击“确定”按钮`、`单击 确定 按钮`、`单击“确定”` 等是否包含“按钮”二字或引号样式；只要控件名称正确、动作匹配且含义清楚即可。
- **例外**：触屏端可用“点击/轻触”；拖拽、旋钮、代码编辑器等控件按真实交互描述。无法访问当前 UI 时标待核验，不猜名称。

检查顺序：先查真实敏感信息与云资源 ID；再核验代码/命令；核对正文与输入输出；对删除、覆盖、授权、网络暴露、计费和生产变更升级风险；最后在当前界面证据下检查 UI 和键盘。
