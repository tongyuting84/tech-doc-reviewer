# 评审与校对流程

## 文档读取策略

先按链接类型选择读取路径，避免混用工具或在预览页失败后误读其他版本。

- `vsop-online.bytedance.net` 链接：使用 `volc-doc` Skill 读取文档。若当前环境没有 `volc-doc`，先询问用户是否安装；用户确认后，使用 [AgentBuddy volc-doc](https://skills.bytedance.net/skill/skills:skills.byted.org/coze/cozedoc/volc-doc) 安装最新版本，再继续读取。
- 公网链接：使用以下 Plan A/B 降级逻辑，不使用 `volc-doc` 代替公网抓取。
  1. **Plan A（优先）**：清理 URL 中的不可见字符，优先通过轻量请求或页面 DOM/fetch 提取正文区（H1 及以下），忽略侧边栏、导航栏、页脚等网页外壳。
  2. **Plan B（仅在 Plan A 无法取得正文时）**：使用已登录的本地浏览器打开目标页；对于前端渲染、`about:blank#blocked`、提取超时等情况，控制目标标签页自动滚动、逐屏截图并通过 OCR 合并正文。执行时确保目标页面在 Chrome 前台可见。
- **硬性约束**：预览（preview）链接读取失败时，只能继续尝试该预览页的 Plan B，或请用户提供正文；严禁降级读取对应的已发布线上版本，也不得用发布版内容替代预览版完成评审。

## 执行顺序

1. 收集标题、URL、载体、文档类型、目标读者、使用人和可用证据。
2. 确定评审尺度：单篇、跨文档或文档库；区分正文、网页外壳、抽取文本、截图和代码。
3. 按 `SKILL.md` 渐进加载：可判定问题读 `rules/`；解释质量方向读 `principles/`；写作或重构才选 `methods/`。
4. 先查 P0 候选：安全、隐私、侵权、真实资源信息、高危命令和严重生产风险。
5. 再查事实、参数、前提、步骤、中间状态、验证、失败/回滚、完整性与一致性。
6. 最后查语言、结构、介质和格式；链接必须跟随完整跳转链并抓取最终页面正文、标题或状态提示，分别验证可达性、目标语义一致性和锚点落点，严禁仅凭 HTTP 200、最终 URL 或路由名称判定通过；库级任务再查生命周期、全局一致、重复、维护性与新鲜度。
7. 合并同源重复问题。每条记录原文锚点、规则 ID、证据、影响、等级和可执行建议。
8. 按 `report-format.md` 生成汉堡包五段式报告。
9. 正式评审若发现问题，按 `quality-record-workflow.md` 写入；无问题不写。失败必须明确说明。

## 证据状态

- **已确认**：原文、渲染、可访问链接或权威资料足以支持结论。
- **疑似**：存在高风险信号，但缺少真伪、版本或权限证据；进入人工确认，不计确定错误。
- **无法核验**：工具、权限或载体缺失；明确写出未检查范围。

## 修改边界

允许：
- 重排已有信息、拆分句段、统一术语、消除歧义；
- 补出文档承诺任务所必需的前提、风险、验证和失败处理，但无事实依据时只描述“需补什么”；
- 在可靠材料支持下补充事实并标依据；
- 文档库任务中给出阅读路径、去重和维护方案。

禁止：
- 无依据创造产品能力、默认值、步骤、兼容范围、性能结论或业务承诺；
- 把原则或方法伪装成机械硬规则；
- 把旧平台视觉细节、团队量化建议或“图 > 表 > 文字”当通用门禁；
- 把网页抽取后遗症当正文错误；
- 在没有库级证据时断言全局结构、重复或新鲜度问题。
